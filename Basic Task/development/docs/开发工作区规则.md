## 2. 六条硬性规则

| # | 规则 | 理由 |
|---|---|---|
| **R1** | **禁改区一个字节都不改。** 包括不修改、不重命名、不删除、不移动 | 题面是评审基准；改了无法自证 |
| **R2** | **所有产出只在 `development/` 内。** 不放仓库根、不放 `Basic Task/` 下、不放禁改区 | 提交标准明确要求 |
| **R3** | **模型文件、引擎源码、编译产物、KV 快照永远不进仓库** | `.gitignore` 已排除；GitHub 单文件上限 100 MB |
| **R4** | **密钥永不进仓库。** 用环境变量；仓库只放 `.env.example` | 题目明确要求 |
| **R5** | **每次提交前先看 `git status`**，确认没有意外文件被 `git add` | 防止误提交模型/密钥/临时文件 |
| **R6** | **不删除或改写 `development/*/README.md` 的原有内容**，只在其后追加 | 那是题目给的目录说明 |

## 3.1 根目录 `.gitignore`（已建立，实测生效）

### 为什么需要它

题包给的两个 `.gitignore` **分别在 `Basic Task/` 和 `Advanced Task/` 里**。
git 的规则是：**`.gitignore` 只对它所在目录及其子目录生效**。

```
Basic Task/.gitignore      → 只管 Basic Task/ 下面
Advanced Task/.gitignore   → 只管 Advanced Task/ 下面
仓库根目录                  → ⚠️ 原本没有任何保护
```

**实测证据**（建立前）：

| 路径 | 结果 |
|---|---|
| `Basic Task/models/x.gguf` | ✅ 被忽略 |
| `Basic Task/development/models/x.gguf` | ✅ 被忽略 |
| **`models/x.gguf`（根目录）** | ❌ **未被忽略** |
| **`llama.cpp/x.cpp`（根目录）** | ❌ **未被忽略** |
| **`.env`（根目录）** | ❌ **未被忽略** ⚠️ 最危险 |

### 已建立的文件

`<仓库根>/.gitignore`（新增文件，**未修改题包的任何一个 .gitignore**）

### 建立后的实测结果

| 路径 | 结果 |
|---|---|
| `models/x.gguf` | ✅ 已保护 |
| `llama.cpp/x.cpp` | ✅ 已保护 |

| `.env.example` | ✅ 可正常提交（`!.env.example` 例外规则） |

### ⚠️ 一条教训（2026-10-09 实际发生）

**验证 `.gitignore` 时，不要用"创建真文件再删除"的方式测试已存在的真实文件。**

当时的错误做法：

```bash
probe() {
  touch "$1"      # ⚠️ 对已存在的 README.md，touch 无害
  git check-ignore -q "$1"
  rm -f "$1"      # ⚠️ 但对 README.md，这一步把它删了！
}
probe "README.md"   # ← 事故：题包的 README.md 被删
```

**结果**：`git status` 显示 `D README.md`（55 行被删）。
**恢复**：`git restore README.md`（一条命令复原，因为它在 git 存档里）。

**正确的验证方式**——不碰真实文件：

```bash
git check-ignore -q --no-index "models/x.gguf"     # --no-index 不要求文件真实存在
```

**这条教训本身也值得写进报告**：它演示了"版本控制的价值"和"测试要隔离真实数据"。

## 5. 每次工作的标准动作

```bash
# ① 进仓库
cd ~/antlab/ANTLab-Infra-Tasks

# ② 开工前确认干净
git status --short          # 应为空，或只有你正在做的改动

# ③ 只在 development/ 里改

# ④ 提交前检查（关键）
git status --short
git diff --stat
#    ⚠️ 确认没有：*.gguf、.env、_work/、llama.cpp/、大文件

# ⑤ 提交（信息要说明目的）
git add "Basic Task/development/..."
git commit -m "feat(control): 实现 /api/status 聚合接口"

# ⑥ 推送
git push origin master
```

## 6. 边界自检清单（提交前逐条过）

| 检查 | 命令 | 期望 |
|---|---|---|
| 禁改区未被修改 | `git status --short \| grep -E "^( M\|M \| D)"` | 只出现 `development/` 下的路径 |
| 无模型文件 | `git status --short \| grep -iE "\.gguf\|\.safetensors"` | 空 |
| 无密钥 | `git status --short \| grep -iE "\.env$\|\.env\."` | 空（`.env.example` 除外） |
| 无临时区 | `git status --short \| grep "_work/"` | 空 |
| 无引擎源码 | `git status --short \| grep "llama\.cpp/"` | 空 |
| 报告与结果在 | `ls "Basic Task/development/results/" "Basic Task/development/reports/"` | 有内容 |

## 7. 与题目要求的对应

| 题目要求 | 我们的落点 |
|---|---|
| Fork 后在自己仓库开发 | origin = `YINXIA-LEARN/ANTLab-Infra-Tasks` ✅ |
| 按开发过程组织提交 | 每个功能/修复一个 commit，信息说明目的（规则 R5） |
| 最终版本放默认分支 | `master`（当前） |
| 提交仓库链接 + 分支 + commit SHA | 截止前登记 |
| `development/` 首页注明模型信息、运行入口、报告位置、数据位置 | `development/README.md`（规则 R1 允许更新它，因为题目要求更新） |
| 模型/引擎/依赖放本地 | 规则 R3 |
| 密钥用环境变量 | 规则 R4 |

> ⚠️ **一处需要澄清**：`development/README.md` 属于"题目给的说明文件"，
> 但题目**明确要求"完成项目后，请更新本文件"**——所以它**是允许修改的**，
> 属于开发区而非禁改区。规则 R6 约束的是"不要删掉原有内容"，不是"不能改"。
